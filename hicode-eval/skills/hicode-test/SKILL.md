# HiCode 公开题评测

使用仓库 `hicode-eval/eval.sh` 和现有看板（默认 8878）。先解析本 Skill 的真实目录，再向上定位包含 `hicode-eval/src/cli.ts` 的 checkout；顶层 `src/` 是被测 HiCode，不是评测器。

## 按用户意图工作

- **选题 / 准备环境**：读取 [准备流程](references/preparation.md)，交付确定的题组、环境证据和待提交 JSON。准备不调用模型、不创建真实运行批次。
- **启动测试**：读取 [操作与证据](references/operations.md)，核对代码版本、服务和题组后提交一次。用户只要求启动时，确认实际运行便交付，不持续等待整批结束。
- **分析已有结果**：先读一次状态汇总，再查异常证据；不因此重跑或修改分数。
- 首次接手本机读取 [环境定位](references/local-environment.md)。它只提供路径线索，实时状态以服务和回执为准。

用户要求先准备、等待代码完成时，只准备题包和环境。待测 payload 留空或明确标记待冻结；不能借用旧服务版本声称已测试最新代码，也不建立后台自动提交或轮询代码完成的任务。用户确认代码就绪后，再核对版本并冻结 payload。

## 执行约定

保留用户的选题、模型、并发、网络和时间约定。并发由服务和批次共同限制，最多 5；没有约定时用 2。研发评测默认每题 `max(1800, 上游 agent.timeout_sec)` 秒；正式复现遵守用户指定条件。一个批次可包含不同单题预算，任务格式为 `{id, agentSeconds}`。

真实提交前简述题组、冻结版本、模型来源、并发及预算。同名题跨数据集时，提交项必须明确包含 `dataset`；成绩和环境绑定按 `(dataset,id)` 区分。Key 只用于鉴权，配置只记录环境变量名。提交超时先查是否已经落盘，不能盲目重提。源码修改、环境准备、正常运行分开记录；不要为了已有环境的提交重新安装依赖或重复全仓验证。

每题独立尝试一次，由原 verifier 自动判题，不追加人工纠错提示、不自动重试失败题。固定源码 payload、题包与镜像身份都保存到运行证据；复用历史题包不复用历史模型修改后的工作区。重新评测产生新成绩，保留累计历史记录。

## 环境与输入边界

公共底座来自审定 Dockerfile、官方镜像摘要和 HiCode 锁文件；共享依赖来自声明配方，特殊准备层按需增加。每次尝试独立容器、网络、Home 和可写层，证据及成绩落盘后销毁。准备容器只缓存固定 HiCode payload，不安装题目依赖，不导入旧评测卷或旧机文件。

题包、模型配置、临时选题和运行记录都放仓库外。SWE 输入为外部审定冻结 bundle，评测器不生成原始 SWE 题包。Terminal 2.0、2.1 分别按 `config/terminal-bench.json`、`config/terminal-bench-2.1.json` 校验；同名题不能混用版本或成绩。不能仅凭题目 ID、历史通过或 `environmentPrepared=true` 判断新镜像就绪；以源哈希、当前配方、镜像可用性和必要运行条件为准。

默认 isolated：做题进程只能经每题模型网关访问固定接口；普通外网不可用。依赖在镜像构建阶段准备，不能在作答或判题时临时修环境，也不能因准备失败偷偷改 open。需要外网的题显式记录网络条件。私有判题材料、参考解和真实 Key 不进入 Actor 或依赖配方。

不修改原题面、输入内容、断言或评分来凑通过率；缺少适配明确记录。不会手绘替换题目图片或把准备检查、假模型烟测记成真实通过。

## 运行、异常与结果

沿用同一服务、页面和数据根。活动任务期间不换 payload、不重启服务或停止容器。当前没有自动完成通知、运行中修改并发的 API；不要声称已绑定这些能力。用户追问进度不等于取消授权。

普通失败由调度器补位。`needs_recovery` 会全局停调度：先核对现场，再使用现有 recover；证据不足保留阻塞，不擅自取消整批或放宽权限。需要监督到结束时用有界 wait，不每几秒查询或重复读取完整日志。

通过要求 `execution=completed`、`grading=passed`、`collection=complete`。超时但判题通过、模型答错、环境/框架异常、取消分别记录；归属不明保留不确定性。正常通过只保存结果，异常查 TUI、事件、判题输出及必要请求片段，分享前脱敏。

台账保留 passed/unpassed/untested，running 从实际任务派生。用户授权历史清理时用 archive-runs 预览和执行，保留精简成绩与证据；题包和镜像不在清理范围。恢复结果不调用模型，用户主动 retry 才创建新尝试，不能改旧分数。命令与证据路径见 [操作与证据](references/operations.md)。不自动 commit/push。
